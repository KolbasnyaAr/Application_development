## 1.1 Сложность O(n²): 
Для решения «в лоб» (brute-force) с двумя вложенными циклами сложность следующая:
 * По времени (Time Complexity): O(n²)
   Внешний цикл выполняется n раз, а внутренний — в среднем n/2 раз. Суммарное количество итераций равно n(n - 1) / 2, что в худшем случае дает квадратичную зависимость от размера входного массива.
 * По памяти (Space Complexity): O(1)
   Алгоритм не использует дополнительные структуры данных (списки, словари) и хранит лишь пару целочисленных переменных для индексов (n, i, j), потребляя константный объем памяти.
   
## 1.2 Сравнение:
Решение через HashMap работает значительно быстрее, так как вместо полного перебора всех пар во вложенных циклах
мы заменяем внутренний поиск на операцию проверки ключа в словаре, которая в среднем выполняется 
за O(1). На практике тест LeetCode для HashMap отработал за 0 мс вместо 1772 мс в первом варианте, переместив алгоритм из 
медленных 10% в лидеры ценой лишь незначительного расхода памяти (20,35 МБ против 19,66 МБ).

## 2.1 "Ошибки" агента
В данной работе использовался Gemini 3.8, и у него нашлась только 1 ошибка: в 17 строке кода ДЗ-1 return seen[complement], i записал return [seen[complement], i]. Ответ в этом случае 
вывелся в [[]], а не в [] как положено. LeetCode не засчитал ответ, написанный агентом, верным. Как он это прокомментировал: "Загадка с двойными скобками [[0, 1]] решилась:
Когда в коде написано return seen[complement], i (без скобок), Python возвращает кортеж. Платформа LeetCode при проверке оборачивает вывод некоторых тестов в свой внутренний формат 
отображения, из-за чего кортеж или несовпадение типов показались на экране как [[0, 1]]."
